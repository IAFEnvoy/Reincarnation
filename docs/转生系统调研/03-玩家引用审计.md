# References pointing at the player

**Target:** Minecraft 26.1.2 decompiled + NeoForge patches, `E:\Java\_mcsrc_26.1.2\net\minecraft\...`
All paths below are relative to that root. All line numbers were read from the files, not guessed.
Nothing in the source tree was modified.

**Question answered:** which *other* objects hold a reference to a specific player (UUID / name / live object),
such that a "wipe this player and start over" feature leaves dangling or stale references.
The player's own data is out of scope except where it creates a *reverse* link.

## 7. Practical implications

### 7a. What a runtime wipe **can** enumerate and purge

**Loaded entities** — `server.getAllLevels()` → `ServerLevel.getAllEntities()` / `getEntities()`, plus `ServerLevel.players()` (`ServerLevel.java:1530`). For each entity you can reach:

- `TamableAnimal.getOwnerReference()` / `setOwner(null)` (`TamableAnimal.java:159`, `:163`) — covers **Wolf, Cat, Parrot, Nautilus** and every other pet.
- `AbstractHorse.setOwner(null)` (`AbstractHorse.java:182`) — covers all equines/camels/llamas.
- `NeutralMob.stopBeingAngry()` (`NeutralMob.java:134`) — the single call that clears `"angry_at"` on Bee/Wolf/PolarBear/IronGolem/ZombifiedPiglin/EnderMan.
- `LivingEntity.setLastHurtByPlayer((Player) null, 0)` (`:629`) and `setLastHurtByMob(null)` (`:642`) — the two highest-volume leaks.
- `Brain.eraseMemory(...)` for `ANGRY_AT` / `LIKED_PLAYER` (`PiglinAi.java:775`, `Allay.java:305`).
- `Projectile.setOwner((Entity) null)` (`Projectile.java:56`), `AreaEffectCloud.setOwner(null)` (`:298`), `EvokerFangs.setOwner(null)` (`:46`), `ItemEntity.setThrower(null)` / `setTarget(null)` (`:423` / `:410`).
- `Leashable.dropLeash(...)` / `setLeashData(null)` (`Leashable.java:123`).
- `Villager.getGossips()` → `GossipContainer.remove(uuid, type)` or `clear()`, and `getGossipEntries()` (`GossipContainer.java:43`) to find the UUID.
- `VaultServerData`/`TrialSpawnerStateData`/`SkullBlockEntity`/`ConduitBlockEntity`/`SignBlockEntity` **if the owning chunk is loaded** — via `Level.getChunk(...).getBlockEntities()`; the vault/trial-spawner setters are package-private or absent, so most of these need an access transformer anyway.
- `Warden.clearAnger(entity)` (`Warden.java:439`) — **but this does not clear `angerByUuid`**, so the persisted UUID survives (see 7c).

**SavedData** — reachable *only by known type* (`SavedDataStorage.get(type)`, `:85`; `cache` is private, `:43`):
- `Raids` via `ServerLevel.getDataStorage().get(Raids.TYPE)` → but `raidMap` and `heroesOfTheVillage` are private with no accessor ⇒ **reflection required**.
- `CustomBossEvents` via the overworld `SavedDataStorage.get(CustomBossEvents.TYPE)`; `CustomBossEvent.removeAllPlayers()` `:56-62` clears the persisted UUID set, but `removePlayer(ServerPlayer)` `:48` needs the **online** object.
- `ScoreboardSaveData` via `get(ScoreboardSaveData.TYPE)`, or better `server.getScoreboard().resetAllPlayerScores(...)` / `removePlayerFromTeam(name)` — all **name**-keyed.

**Player account state** — `PlayerList.remove(player)` (`:314-348`), `ServerOpList`/`UserBanList`/`UserWhiteList.remove(NameAndId)`, `CustomBossEvents.onPlayerDisconnect(player)` (`PlayerList.java:337`).

### 7b. What is **practically unpurgeable** at runtime

1. **Anything in an unloaded chunk.** Entity NBT and block-entity NBT for chunks outside every player's loaded set is unreachable from the server. Since `ServerLevel` keeps no player-keyed persistent index, the only way to sweep them is to **rewrite region files offline** (or force-load every chunk). This covers `VaultServerData.rewardedPlayers`, `VaultSharedData.connectedPlayers`, `TrialSpawnerStateData.detectedPlayers`, `SkullBlockEntity.owner`, `BeehiveBlockEntity.stored` bees, `ConduitBlockEntity.destroyTarget`, and every unloaded mob's `lastHurtByPlayer` / `angry_at` / `LoveCause` / `Trusted` / gossip.
2. **Private state with no accessor** — needs reflection / an access transformer / a mixin:
   - `Raid.heroesOfTheVillage` (`Raid.java:108`) — no getter, no remover.
   - `AngerManagement.angerByUuid` (`AngerManagement.java:49`) — `clearAnger` never touches it.
   - `Interaction.attack` / `.interaction` (`Interaction.java:37-38`) — private field of a private record.
   - `BeehiveBlockEntity.stored` / `getBees()` (`BeehiveBlockEntity.java:87`, `:337`) — both private.
   - `Fox.clearTrusted()` (`Fox.java:452`) — private (the underlying `EntityDataAccessor`s are private static finals too).
   - `PrimedTnt.owner` (`PrimedTnt.java:51`) — no setter at all.
   - `ZombieVillager.startConverting` (`:200`) — private, and it also resets the conversion timer.
   - `Animal.loveCause` (`Animal.java:46`) — private, no setter; `resetLove()` does **not** clear it.
3. **Files with no delete API**: `PlayerDataStorage` (`world/level/storage/PlayerDataStorage.java`) exposes only `save`/`load`/`backup`; `world/stats/<uuid>.json` and `world/advancements/<uuid>.json` are written but never deleted by vanilla. A wipe must delete files directly (and the `.dat_old` / `_corrupted_*` variants).
4. **Name-keyed state is not UUID-correlated**: scoreboard scores, `PlayerTeam` membership, `WrittenBookContent.author`, and map player-decorations use the **scoreboard name / display name**. A wipe-plus-recreate under the same name silently inherits credit; a rename orphans it. There is no `UUID → name` index you can invert reliably other than `CachedUserNameToIdResolver` / `usercache.json`.
5. **`ServerPlayer.enderPearls`** (`ServerPlayer.java:270`) is serialized into the player's own `.dat` (`:501-510`). A "delete the entity, then re-create the player from the existing file" strategy resurrects ender pearls whose shooter no longer exists.
6. **`CustomBossEvent.removePlayer` takes a live `ServerPlayer`** (`CustomBossEvent.java:48`), so an offline player's UUID cannot be removed from a persisted boss-bar visibility set without `removeAllPlayers()` or reflection.

### 7c. Two concrete correctness gaps worth flagging to the implementer

- `Warden.clearAnger(Entity)` → `AngerManagement.clearAnger(Entity)` (`Warden.java:439`, `AngerManagement.java:157-161`) removes only the **live** entries (`angerBySuspect`, `suspects`). The persisted `angerByUuid` (codec field `"suspects"`, `:53`) keeps the UUID, and `convertFromUuids` (`:128-141`) will re-bind it to the re-created player. Same shape applies to `Raid.heroesOfTheVillage`.
- `EntityReference` fails **soft**, so most dangling references are *silent*, not crashes: `getEntity` returns `null` and demotes the live ref to a bare UUID (`EntityReference.java:55-76`). No unguarded owner deref was found — every consumer null-checks (`AbstractArrow.java:590`, `ShulkerBullet.java:191`, `FishingHook.java:152-154`, `LightningBolt.java:167`, `TntBlock.java:129-135`, `EvokerFangs.java:103-105`). The damage is therefore *stale data + wrong gameplay*, not exceptions.

### 7d. Recommended sweep order

1. Kick + `PlayerList.remove` (clears `playersByUUID`, `stats`, `advancements` maps and boss-bar connection).
2. Entity pass over **all loaded levels**: `setLastHurtByPlayer(null,0)`, `setLastHurtByMob(null)`, `stopBeingAngry()`, `setOwner(null)` (TamableAnimal + AbstractHorse), `Brain.eraseMemory(ANGRY_AT/LIKED_PLAYER)`, `ItemEntity.setTarget/setThrower(null)`, `Projectile.setOwner(null)`, `dropLeash`.
3. Loaded block entities: vault / trial spawner / skull / sign / conduit / beehive.
4. SavedData by explicit type: `Raids`, `CustomBossEvents`, overworld `scoreboard` (+ `MapItemSavedData` via `MapIndex` ids).
5. Name-keyed: `Scoreboard.resetAllPlayerScores` + `removePlayerFromTeam`.
6. Account files: `ops.json`, `whitelist.json`, `banned-players.json`, `usercache.json`, `world/playerdata/<uuid>.dat*`, `world/stats/<uuid>.json`, `world/advancements/<uuid>.json`.
7. Offline NBT/region rewrite for everything in unloaded chunks — the only complete option for the persisted holders.

## 8. Explicit unknowns / caveats

- `StructureBlockEntity.author` (`world/level/block/entity/StructureBlockEntity.java:58`, saved `:82`) — a persisted free-form `String` that *could* hold a player name. No vanilla call site writes a player into it; **UNKNOWN / probably dead**.
- `Animal.loveCause` — persistence is confirmed (`"LoveCause"` at `Animal.java:100`/`:107`), but there is no API to clear it, so the only runtime fix is reflection or overwriting it via a breeding event. Flagged as a design hole, not an unknown.
- `OldUsersConverter` (`server/players/OldUsersConverter.java`) — exists as a legacy migration helper; no player-keyed state of its own. Whether it is still invoked for modern worlds was not traced.
- The exact on-disk NBT tag type of a stored UUID (`UUIDUtil.CODEC` is a 4-int stream, `core/UUIDUtil.java:23-24`) was inferred from the codec, not from a real saved region file.
- Mod-/NeoForge-added capabilities that store per-player state are out of scope (vanilla + NeoForge patches only).
- The block-entity sweep covered the files named in the brief plus a full grep for `UUID` / `EntityReference<` / `Player`-typed fields under `world/level/block/entity`; a small tail of the grep output was not read line-by-line, but no further player-keyed field appeared.
- `BeehiveBlockEntity`'s ability to carry a player UUID depends on a player-targeting bee having `angry_at` set at the moment it enters the hive; the ignore-list evidence (`:55-82` omitting `"angry_at"`) is solid, but no reproduction was attempted.
