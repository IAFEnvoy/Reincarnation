# 寿元系统迁移与数据驱动联动

寿元的权威实现已从 MiXianTu 迁入 Reincarnation。Reincarnation 不依赖 MiXianTu；MiXianTu 将 Reincarnation 作为可选依赖，仅通过隔离的兼容层实现突破增寿，通过可选的注册表引用显示寿元信息。Saturn 提供行为、条件、公式与信息注册表，不保存寿元。

## 账本与时间

每个活体可拥有 `reincarnation:lifespan` 附件，Codec 保存两个 long：`lifespan_remaining` 和 `lifespan_total`，单位均为游戏刻。

| 状态 | remaining | total |
| --- | --- | --- |
| 未记账 | -1 | -1 |
| 有限寿元 | 0 或正数 | 不小于 remaining |
| 关闭账本 | -1 | 0 |

`total` 是本世累计获授寿元，不是会自动恢复的上限。`set(n)` 同时写两项；正 `add(n)` 同增两项；负 `add(n)` 只减剩余，最低为 0。零增量不创建附件；正溢出饱和到 `Long.MAX_VALUE`。向未记账实体首次 add 时以配置基数起算，关闭账本后 add 则从 0 起算。

时间按世界 gameTime 的全局周期结算，只计算在线且被 tick 的实体，离线不补扣。玩家可自动开账；普通生物只有显式写入或已经持有账本才参与，避免为所有生物创建附件。普通死亡按 `copyOnDeath()` 保留账本；完整换世重开账本，不把寿元加入 `keep_on_rebirth`。

## 配置

Jupiter 服务端配置新增 `lifespan` 分类。所有寿元数字均以刻为单位，岁数仅为显示换算。

| 键 | 默认 | 行为 |
| --- | --- | --- |
| `enabled` | false | 控制自动初始化、结算、寿尽及提醒；显式 API/指令/行为仍可用 |
| `base_lifespan` | 1440000 | 初始和新世寿元；默认按 24000 刻/岁显示为 60 岁，0 不自动开账 |
| `settle_interval` | 20 | 每隔多少游戏刻结算 |
| `age_per_settle` | 20 | 每次扣除的寿元；0 不自然老化 |
| `on_expire` | DEATH | NONE / DEATH / REINCARNATE |
| `player_death_mode` | KILL | KILL 触发正常死亡；SPECTATOR 只切旁观模式 |
| `player_rebirth_mode` | NEW_LIFE | NEW_LIFE 完整换世；RESET 原地重置；CONFIGURED 回退 NEW_LIFE |
| `warning_fraction` | 0.1 | 剩余比例不高于阈值时在聊天栏提醒一次；已低于阈值时补发，增寿恢复后允许再次提醒；0 禁用 |
| `ticks_per_year` | 24000 | 显示为岁的除数，1 显示刻数，不改变实际流逝速度 |
| `age_creative` | false | 创造玩家是否老化 |
| `age_spectator` | false | 旁观玩家是否老化 |
| `kill_on_reset` | false | 原地重置完成后以寿元伤害击杀；完整换世不额外击杀 |

Jupiter 配置文件中的枚举使用上述大写名字；数据表行为的 mode 使用下文的小写名字。

提醒不依赖“上一次数值必须高于阈值”，因此登录时已经低于阈值、调整配置后落入提醒范围的玩家也会收到消息。同一段低寿元状态只提醒一次，增寿后剩余比例恢复到阈值以上则重新允许提醒；0 禁用，1 也有效，无限寿元与总额为 0 不提醒。会话内的提醒状态不写入 Codec，重新加载账本时允许补发。

`NONE` 关闭账本并通知。`DEATH + SPECTATOR` 保留耗尽的账本，不产生死亡事件。`DEATH + KILL` 使用 `reincarnation:lifespan` 伤害类型；若其他模组取消伤害使实体存活，则关闭账本，避免无限重试。开启原有 `lifecycle.auto_reincarnate_on_death` 时，正常寿尽死亡后的重生也会按该配置进入下一世。该路径与 `on_expire=REINCARNATE` 都记录“寿元耗尽”；直接转世无需开启自动死亡转生。死亡事件将原因保存为 `reincarnation:death_reason` 附件中的组件，不借助会在 40 tick 后被原版清空的最近伤害来源；附件可随玩家存档持久化，不复制给重生或新世玩家。

可选 `lifecycle.filter_death_damage_types`（默认关闭）只筛选死亡后的自动转生。开启后，`DEATH + KILL` 路径的最终致死类型须在 `reincarnation:reincarnate_on_death` tag 内；默认包含 `reincarnation:lifespan`，数据包可调整。未命中时普通重生，不归档、不换世。`on_expire=REINCARNATE`、`LifespanApi` 的直接转世请求和指令不受死亡筛选影响。

玩家 `new_life` 调用完整转生事务，归档、推进世代并替换 ServerPlayer；`reset` 保持对象和世代，按通用附件保留规则移除未保留附件，发布扩展重置事件，重建 Saturn 技能和被动属性，并重开寿元。原版背包、经验与进度不属于原地附件重置范围。非玩家始终使用 reset。完整换世在寿元启用时获得配置基数，禁用时保持未记账；原地重置显式按基数重开。完整换世的新寿元在归档时固定，事务恢复不会重新读取改变后的基数。

## Java API

公共入口为 `com.iafenvoy.reincarnation.api.LifespanApi`。只读查询不创建附件；所有写入和转世在逻辑服务端主线程执行，客户端写入返回 `SERVER_ONLY`。

```java
Lifespan before = LifespanApi.get(entity);
Result<Void> extended = LifespanApi.add(living, 24_000L);
Result<Void> rewritten = LifespanApi.set(living, 48_000L);
Result<Void> closed = LifespanApi.unlimited(living);

// Safe inside an action chain or entity tick; success means accepted, not completed.
Result<Void> accepted = LifespanApi.requestRebirth(living, RebirthMode.CONFIGURED,
        Component.translatable("yourmod.reason.rebirth"));

// Only when the caller can handle an immediate player replacement.
Result<LivingEntity> result = LifespanApi.rebirth(living, RebirthMode.NEW_LIFE,
        Component.literal("A new life"));
result.getData().ifPresent(fresh -> {
    // Continue with fresh, not the old player reference.
});
```

Result 使用 Saturn 的 `getFailure()` / `getData()`，均返回 Optional。常规失败返回 `INVALID_VALUE`、`SERVER_ONLY`、`CANCELLED` 等；已提交的完整换世事务异常仍交给原有恢复流程，不能当作普通失败重试。

排队请求按账号去重，服务端 tick 末尾执行，执行前核对实体对象、在线状态、预期世代和寿尽状态。旧玩家已被另一条路径换世、离线或续命后，对应过期请求不再执行。数据包行为、命令和 KubeJS 桥接均使用排队入口，避免链中途替换 Player。

## 事件与联动

事件均发布到 NeoForge 游戏事件总线。

| 事件 | 用法 |
| --- | --- |
| `LifeSpanEndEvent.Pre` | 寿元耗尽前，可取消；通过 API 续命则继续倒计时，未续命的取消关闭账本 |
| `LifeSpanEndEvent.Post` | 寿尽后果已执行；实体和账本属于旧世，`getOutcome()` 为实际分支 |
| `LifeSpanRebirthEvent.Pre` | 所有寿元转世入口共用，可取消；`getMode()` 已解析为 new_life 或 reset |
| `LifeSpanRebirthEvent.Reset` | 通用附件清理后、技能和寿元重建前的扩展入口；仅原地重置触发 |
| `LifeSpanRebirthEvent.Post` | 转世成功，新实体与新账本；完整换世后使用此实体继续操作 |
| `LifeSpanRebirthEvent.Failed` | 排队转世失败/取消，包含 `getFailure()`；不要把接受请求当作完成 |

显式转世不发布 End；寿尽转世同时经过 End 和 Rebirth 两组事件。完整换世的附件继承统一由 `keep_on_rebirth` 和附件自身的死亡复制规则处理。只有附件之外的状态需要注册 `ReincarnationHandler`，不要只在 Post 复制数据：handler 的归档数据会随事务保存，reset/recover 必须幂等。End Post 的账本是耗尽时的独立副本，原地重置或关闭账本不会覆盖通知中的结束数值。Post/Failed 仅为通知，其监听器异常不会撤销已经完成的操作。

## 数据表行为

以下类型注册到 Saturn 的实体行为类型表，能用于任意 EntityAction 槽位，非活体目标不操作。没有另建寿元数据表。

### `reincarnation:add_lifespan`

增加剩余寿元和本世累计授予总额。`amount` 必填，为 NumberProvider，支持常量与公式，单位为刻。数值按 Math.round 换成 long；常量与公式的结果均须有限且非负，无效结果在执行时跳过。零数量不修改账本，也不为未记账目标开账。

```json
{"type":"reincarnation:add_lifespan","amount":24000}
```

### `reincarnation:remove_lifespan`

只扣剩余寿元，最低到 0，不减少本世累计授予总额。`amount` 的格式、校验和取整与增寿行为一致，使用非负数量表示扣除量。

```json
{"type":"reincarnation:remove_lifespan","amount":1200}
```

### `reincarnation:reincarnate`

`mode` 默认为 configured，可选 configured / new_life / reset；`reason` 为可选聊天组件，默认使用转世翻译。始终排队执行。

```json
{"type":"reincarnation:reincarnate","mode":"new_life","reason":{"text":"服用转世丹"}}
```

### `reincarnation:unlimited_lifespan`

关闭账本，直到显式 set/add 重新授予有限寿元。

```json
{"type":"reincarnation:unlimited_lifespan"}
```

## 数据表条件

以下类型注册到 Saturn 的实体条件类型表，不创建账本。

### `reincarnation:lifespan`

`field` 默认为 remaining，还可选 total / fraction / spent。fraction 为剩余/总额，总额为 0 时按 0；spent 为 total-remaining。比较字段使用 Saturn Comparison 的 `comparison` 与 `compare_to`。非有限寿元恒为 false，避免把 -1 当作负寿元。

```json
{"type":"reincarnation:lifespan","field":"fraction","comparison":"<","compare_to":0.1}
```

### `reincarnation:lifespan_state`

`state` 必填：finite（剩余非负，包含耗尽）、unlimited（未记账或关闭）、unaccounted（从未记账）、expired（剩余为 0）。

```json
{"type":"reincarnation:lifespan_state","state":"expired"}
```

### `reincarnation:generation`

仅服务端玩家有效，比较玩家可见的世代编号，从 1 开始。

```json
{"type":"reincarnation:generation","comparison":">=","compare_to":2}
```

公式变量仍为 `lifespan_remaining` / `lifespan_total`；负值哨兵读作 NaN。大整数转公式 double 时具有普通 double 的精度限制。

## 指令与信息

`/lifespan [get [targets]]` 查询；`set <targets> <ticks>`、`add <targets> <ticks>`、`unlimited <targets>` 和 `reincarnate <targets>` 写入或提交转世。所有节点需要管理员权限。reincarnate 的成功反馈表示请求已接受。

Saturn getter 与 expression type 均为 `reincarnation:lifespan`，row 为同名 ID，importance 为 70。默认加入世代信息 life tag；MiXianTu 的 cultivation tag 也引用此行。在线、快照和历史玩家数据复用同一 getter，不创建历史 Player。未记账不显示，关闭账本显示不受限；已有账本即使禁用自然老化仍可查看。信息行、查询指令和提醒统一显示「当前年龄 / 总寿元」，年龄为 total-remaining，从 0 正向增长；正数增寿只增加总寿元，年龄不变，新世年龄归零。历史保存原始刻数，显示年龄和岁数按当前换算配置。

## 存档与 MiXianTu 接入

新账本保存在实体原有附件数据内，前世数据沿用每世归档和 Saturn 快照，不另开寿元文件。Reincarnation 同时注册 `mxt:lifespan` 兼容附件类型，读取后迁到新 ID；两者并存时新值优先，然后移除旧值。MiXianTu 不再注册旧附件，以免重复。

MiXianTu 已删除境界阶段的 `lifespan` 字段、专用增寿结算及 Java 兼容桥。突破增减寿元由 `success_action` 中的 `reincarnation:add_lifespan` / `reincarnation:remove_lifespan` 配置，可与其他成功行为组成数组。`amount` 接受非负数字或公式，行为类型决定增加或扣除，不再使用 mode；扣除仅影响剩余。可选联动使用顶层 NeoForge 模组加载条件，未安装时排除整个定义及相应引用；运行时条件不能避免未知行为解码失败。两模组生产 Java 代码互不引用。寿元信息行及伤害类型标签使用 `required: false` 引用。命令 `/lifespan`、寿元与转世行为、Java 事件及 KubeJS 插件均由 Reincarnation 提供，MiXianTu 不重复注册入口。

MiXianTu 不注册转世 handler，也不监听原地重置事件，不保存附件的第二份快照。完整换世和原地重置都默认清空修为、层数、天劫、身份、功法、魂等附件。保留项由数据包 `data/reincarnation/tags/neoforge/attachment_types/keep_on_rebirth.json` 声明，例如 `mxt:spirit_identity`、`mxt:technique`、`mxt:soul_stats`。仍要求附件支持死亡复制；完整换世尊重复制处理器，名单固定到归档，恢复不受后续标签变化影响。原地重置不复制对象，保留已选附件的原实例。被清除的附件会在下次访问时创建默认实例，调用方应重新获取附件，不能继续使用重置前保存的旧实例。

通用设置集中到 Reincarnation：`lifespan.kill_on_reset=false`，以及 `reset.clear_resources=true`。关闭清空资源时，将已有 Saturn 资源附件加入保留名单；开启时仍可由附件标签单独保留。`reset.unknown_mod_data=true` 优先于这两种保留选择。资源策略纳入 `ResetPolicy`，随请求持久化；旧请求缺少此字段时按清空解码。原地重置时先清附件、重算技能和被动、重开寿元，再执行可选击杀。完整换世与登录恢复也在统一收尾阶段重算技能和被动，MiXianTu 无需补偿调用。

MiXianTu 的八项转世开关及其翻译键整体移除；不自动跨模组改写配置文件。需要继续保留修炼数据的整合包应提供上述附件标签。已完成的旧世归档继续只读；仍含旧 `mxt:cultivation` handler 的未完成事务须在更新前由对应版本恢复完成。

灵草补算独立为 MiXianTu 炼丹配置 `alchemy.herb_catch_up_ticks`，默认 24000，范围 20..Integer.MAX_VALUE，每 20 刻一期；不再使用寿元的 ticks_per_year。

本次纯数据驱动改造后，MiXianTu 编译及资源处理通过；重新运行同装的 16 项寿元探针和未安装的 1 项突破探针通过，覆盖行为组合、正负增量、失败不授予、链结束不重复授予及条件化定义加载。日志为 MiXianTu 的 `build/lifespan-datapack-present.log` 与 `build/lifespan-datapack-absent.log`。
