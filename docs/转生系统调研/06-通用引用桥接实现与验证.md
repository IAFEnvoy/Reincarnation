# 通用引用桥接：首阶段实现与验证

> 2026-11-02；Minecraft 26.1.2、NeoForge 26.1.2.99、Java 25。
> 对应主方案阶段 A、05 报告的通用 NBT 后端。本阶段不提供玩家转生指令；推进世代不等于完成玩家归档、重建和重置。
>
> 后续更新：完整转生、事务恢复和文字查询已实现，见 [07-转生流程与历史查询实现](07-转生流程与历史查询实现.md)。2026-11-05 已将手写 NBT 元数据处理替换为 Codec 联合编码；本文的结构与接入说明已同步。

## 1. 已实现

生产代码位于 `src/main/java/com/iafenvoy/reincarnation/`，使用 9 个集中 Mixin。没有为狼、狐狸、投射物或任意关系字段编写专用持久化适配器。

| 基础层 | 实际行为 |
|---|---|
| `EntityReferenceMixin` | 添加只设置一次的世代字段；`of(ServerPlayer)` 捕获世代；包装原 Codec；统一修正 `store`、旧主人 UUID 读取；在底层解析的所有返回分支和 `matches` 校验世代，Level 重载通过底层入口生效 |
| `ReferenceCodecs` | 委托原版编解码四整数 UUID，给 IntArrayTag 附加临时戳；读取时恢复引用世代；带戳引用写入未支持的非 NBT 后端返回错误，避免静默丢失世代 |
| `ReferenceStamp.MAP_CODEC`、`ReferenceMetadata.CODEC` | 定义目标 UUID、非负世代、key/index 路径、元数据版本、表项数量及扩展区创建标记；使用原版 Codec 的结构与范围校验 |
| `ReferencePersistence` | 用 DynamicOps 导航通用结构、校验路径及目标，通过 Codec.encode 的 prefix 联合编码完整载荷与旁表；没有 NBT 类型依赖或手写 NBT 字段读写 |
| `IntArrayTagMixin`、`CompoundTagMixin` | 分别持有临时引用戳、完整载荷标记；原版 `copy()` 传播这些字段，不改二进制格式或 equals/hashCode |
| `NbtOpsMixin` | NBT→NBT 转换传播临时戳及载荷标记 |
| `TagValueOutputMixin`、`TagValueInputMixin` | 完整输出建立元数据表；单对象、对象列表输入均在业务解码前使用返回的恢复结果 |
| `SavedDataStorageMixin` | 在 `{data, DataVersion}` 外层封装打包，不改变 data 的业务类型；读取端在业务 Codec 前恢复 |
| `NbtIoMixin` | 文件使用的 named tag 与网络使用的 any tag 在完整二进制读取后恢复表；最终写出时通过 Codec/DynamicOps 返回带最新路径的输出结构，处理打包后复制、移动和列表改动，不修改源数据字段 |
| `SynchedEntityDataMixin` | 集中识别直接引用、Optional 引用的世代变化，避免 UUID 相等阻止服务端实际替换和同步判脏 |

原来的 `ReferenceNbt` 已删除。运行时仍使用真实节点扩展字段保存临时戳，`ReferencePersistence` 中的 IdentityHashMap 仅在一次恢复操作中记录待校验表和节点，不长期持有数据。

`ReferencePersistence.wrap(codec)` 包装完整对象的 Codec：先调用原 Codec 的 `encode(value, ops, prefix)`，再用 `ReferenceMetadata.CODEC.fieldOf(...).codec()` 编码旁表。合并分两步进行：先以已有 `NeoForgeData` 为 prefix 编码元数据，再以已有完整对象为 prefix 编码扩展区。这样根字段和其他模组的扩展字段均保留，不会因重建嵌套对象而覆盖它们。

原版 UUID Codec 输出四整数数组，不能与对象 prefix 合并；`prefix` 不是给任意基本值附加字段的机制。为兼容既有 UUID 字段，本模组保留叶子节点格式，并在完整对象层联合编码。引用路径仍需按实际结构收集，由通用 DynamicOps 完成；版本、路径分段、UUID 和世代的序列化均交给 Codec。

## 2. 元数据与输入状态

使用 05 的布局：`NeoForgeData["reincarnation:reference_metadata"]`，版本 1，表项包含有类型的路径分段、目标 UUID 和非负 long 世代。只有这条精确扩展路径是保留位置；其他位置的同名业务键仍按普通数据处理。

输入先用 Codec 解码整棵树的所有表，验证路径、目标和嵌套冲突后才统一应用节点戳。恢复返回消费旁表后的结构，不修改传入树的字段值或结构；调用方必须接收返回值。任何格式、路径、目标或嵌套表世代冲突导致完整恢复失败，不返回可被当作无戳关系的部分结果。异常使用 `ReferenceMetadataException`，不会被 ValueInput 当作普通 DataResult 错误忽略。

运行中的载荷由临时标记识别。重复进入输入边界时不再次应用已过期的旧路径表；保存仅从当前节点戳重建路径。嵌套完整载荷各自持有表，父表不重复登记子载荷的引用。同 UUID 的多条引用允许各自属于不同世代。

可选字段 `created_extension: true` 表示 NeoForgeData 仅因本模组元数据而创建，消费表后可删除空壳；原本就存在的空 NeoForgeData 和其他模组内容保留。旧表未提供此字段时按未创建处理。删除最后一条引用后不保留空表。

对自行调用 Codec 保存完整对象的第三方，推荐直接联合编解码：

```java
Codec<MyPayload> codec = ReferencePersistence.wrap(MyPayload.CODEC);
Tag encoded = codec.encode(value, NbtOps.INSTANCE, existingPrefix).getOrThrow();
MyPayload decoded = codec.parse(NbtOps.INSTANCE, encoded).getOrThrow();
```

需要在已有边界处理完整载荷时，可调用 `ReferencePersistence.pack(ops, tree)` / `restore(ops, tree)`，两者都返回结果，不能沿用旧版忽略返回值的写法。标准 ValueInput/Output 和 SavedData 路径自动接入。任意业务 Map 不自动成为扩展载体；带戳节点绕过完整载荷封装直接二进制保存时会报错，防止悄悄丢戳。

元数据 Codec 可独立用于 NBT/JSON，新增测试验证两者往返；实际引用节点标记仍由 NBT 后端提供，不能把元数据 Codec 支持 JSON 等同于整套引用持久化已支持 JSON。

## 3. 世代索引与 API

索引使用独立文件 `<world>/data/reincarnation/generations.dat`，在 `ServerAboutToStartEvent` 初始化。`Generations` 只保存当前服务端的一份索引，不再用服务器到索引的 Map；`ReincarnationService.stop()` 同时清除索引缓存，重新启动或进入其他存档时从对应文件加载。它没有采用 SavedData 的容错加载，因为索引读取失败后被当作缺数据重新创建，会让历史引用重新生效。

`GenerationIndex` 使用 `FileAccess.NBT` 和索引 Codec 直接读写，保存成功后才发布内存新值；不使用临时文件、force、原子替换或压缩。`.initialized` 标记用于发现曾初始化过却丢失的索引；已有文件损坏或版本未知会阻止初始化，不默认回到 0。没有自动回退旧备份，不能承诺覆盖中途断电导致的文件损坏。

索引 Codec 由 `RecordCodecBuilder`、`UUIDUtil.STRING_CODEC` 和非负 long Codec 组合，保持原有 `version: 1` 与 `accounts: [{uuid, generation}]` 结构及 NBT 字段类型。列表转 Map 时拒绝重复 UUID，编码按 UUID 排序。解码入口将任何错误转换成不含部分结果的错误，避免 `FileAccess` 接受坏账号被跳过的部分列表。生产代码不再手动读取或构造 NBT。

本次简化通过 `build` 和全部 45 项必需 GameTest（`build/generation-index-validation.log`）。新增 `index_codec` 覆盖既有结构读写、NBT 字段类型、排序、版本、重复 UUID、负世代和坏条目不接受部分结果；`index_lifecycle` 覆盖停止后释放缓存及从文件重新加载。原有索引损坏/丢失拒绝、事务恢复和世代引用测试继续通过。寿元行为测试同步为现有实现的负数执行时忽略语义，未修改行为 Codec。

`Generations.commit(server, uuid, expected, next)` 只接受主线程上连续的一代推进；相同转换重放幂等，写入失败不发布新值。该入口供未来协调器在持久化提交意图后调用，不能单独当作转生功能。

公共引用 API：

```java
EntityReference<ServerPlayer> online = EntityReference.of(player); // 自动捕获世代
EntityReference<ServerPlayer> offline = LifeReferences.bind(level, uuid); // 新 UUID 绑定
EntityReference<ServerPlayer> historical = LifeReferences.restore(uuid, savedGeneration);
OptionalLong generation = LifeReferences.generation(historical);
boolean sameLife = LifeReferences.sameLife(online, historical);
```

无戳旧玩家引用按创世代 0 判定；读取、离线解析、普通死亡或实体重建都不会把它更新为当前世代。非玩家引用和客户端引用保持原版解析行为。网络 StreamCodec 仍是原版 UUID，客户端不承担权威世代校验。

## 4. 实际验证

测试现位于主源码集 `src/main/java/com/iafenvoy/reincarnation/gametest/`，结构资源位于 `src/main/resources/data/reincarnation/structure/gametest/`，随主模组打包。主入口仅在 NeoForge 启用 GameTest 时注册测试函数、附件和处理器；测试统一使用 `reincarnation:gametest/*` 标识。GameTest 服务端使用单独的 `run-game-tests` 目录，加载实际生产 Mixin。

```powershell
.\gradlew.bat --offline --no-configuration-cache build runGameTestServer
```

| GameTest | 验证内容 |
|---|---|
| `persistence` | 标量、列表、Map 自动往返；同 UUID 不同世代、世代 0；原版 UUID 形状与网络格式；store/read/旧主人 UUID 分支；原有空扩展区保留；非 NBT 后端拒绝丢戳 |
| `codec_composition` | 实际 encode(prefix) 联合编码；保留根字段和其他模组扩展字段；前缀及解码输入结构不被修改；UUID 数组格式；元数据 Codec 的 JSON 往返；已有前缀被覆盖字段后重建路径表 |
| `copy_and_move` | 实际 copy/merge、NbtOps 转换、嵌套载荷经 FriendlyByteBuf 网络 NBT 往返、移动后路径更新、同 UUID 新戳不被旧表覆盖、同名业务键、重复打包与删除空表 |
| `invalid_metadata` | 错误目标、负世代、未知版本、重复路径、数组原地修改、未封装引用、嵌套冲突被拒绝；失败恢复不部分写戳 |
| `generation_and_cache` | 实际 ServerPlayer 绑定与世代推进；缓存快路径、Level 重载和 matches 拒绝旧世；离线后恢复与普通同世实体替换 |
| `synced_owner_and_reload` | 真实狼的同 UUID 主人替换服务端值并判脏；完整实体保存→压缩 NBT→加载后世代仍在 |
| `saved_data` | 业务载荷是裸引用列表的 SavedData，真实落盘后重新建立存储实例并读回两条不同世代引用 |
| `index_recovery` | 索引落盘重开、转换幂等、禁止跳代，损坏或丢失的已初始化索引不重置为 0 |

首轮 7 项结果保留于 `build/reference-verification.log`。Codec 改造新增 `codec_composition` 后，引用基础测试共 8 项，与转生、归档、恢复、原因组件及信息页组成完整 **28 项必需 GameTest，全部通过**；build 通过。最新日志为 `build/reference-codec-build.log`、`build/reference-codec-gametest.log`。
